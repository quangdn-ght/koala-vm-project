# Plan: giám sát healthy web service (GET domain)

**Mục tiêu:** probe định kỳ các domain công khai bằng GET, theo đúng đường đang chạy:

```
web client GET domain
        │
 blackbox-exporter :9115  (module mới, host network)
        ▲ scrape 1m
 prometheus :9091  ──►  grafana :3000   (dashboard websites + fleet)
        │ evaluate 15s
        │ alerts.yml  WebsiteHTTPDown
        ▼
 alertmanager :9093
        │ webhook POST /alerts/event/prometheus
        │ basic_auth api_key / KEEP_WEBHOOK_API_KEY
        ▼
 keep-backend :8080  ── keep-frontend :3001 inbox
```

**Không** nhét URL public vào `prometheus/targets/http.yml` / job `blackbox-http` hiện tại. Job đó phục vụ HTTP nội bộ (IP guest/physical/aibox/oraybox), module `http_2xx` chấp nhận 301/302, bỏ verify TLS, không kiểm tra body Kong, và `AppHTTPDown` bắt buộc ICMP cùng `vm`/`host`.

**Không** đổi RAM guest, migrate VM, libvirt, Telegram, Grafana password.

---

## 0. Quyết định kiến trúc

### 0.1 Probe ở đâu

Prometheus đã scrape blackbox `host.docker.internal:9115` (`network_mode: host`). Domain public resolve từ hypervisor `ght-faceid-server` — cùng chỗ đang ping/HTTP nội bộ. **Không** thêm exporter mới, **không** healthcheck trong Keep.

### 0.2 Job riêng `blackbox-http-website`

| | Tái dùng `blackbox-http` + `http*.yml` | Job mới (chọn) |
|--|----------------------------------------|----------------|
| Glob `http*.yml` | `http-websites.yml` bị scrape bởi `http_2xx` | File `targets/websites.yml` không khớp glob |
| Module | 200/301/302, skip TLS, không body | Module `http_website`: 200 cuối, TLS, body |
| Scrape | 15s (nặng với HTTPS + redirect) | **1m**, timeout 20s (giống aibox/oraybox) |
| Alert | Dính `AppHTTPDown` + ICMP gate | Rule riêng `WebsiteHTTPDown` |
| Dashboard | `role=~"guest\|physical"` không đếm website | `role=website` tách panel |

### 0.3 Inventory là nguồn sự thật (pattern AI Box / Oraybox)

- `monitoring/websites/sites.json` — sửa tay duy nhất khi thêm/bớt domain
- `python3 scripts/gen-website-targets.py` → `prometheus/targets/websites.yml` (generated, không sửa tay)
- Reload Prometheus `POST :9091/-/reload` (file_sd cũng refresh 30s)

### 0.4 Định nghĩa healthy (user)

Probe **thành công** khi **đồng thời**:

1. GET, follow redirect, **status cuối = 200** (không chấp nhận 301/302 làm kết quả cuối)
2. Body **không rỗng** (`fail_if_body_not_matches_regexp: ".+"`)
3. Body **không** chứa thông báo Kong no-route (regex case-insensitive)
4. URL `https://` → TLS verify bật (`fail_if_not_ssl: true`, `insecure_skip_verify: false`)

Fail nếu timeout, DNS fail, TLS fail, 4xx/5xx (kể cả Kong 404 JSON), body rỗng, hoặc HTML/JSON Kong “no Route matched” dù status 200.

### 0.5 ICMP

**Không** ping domain public và **không** `and on(host) probe_success{icmp}` — nhiều site chặn ICMP; mất ping không có nghĩa web chết. Đây là `class: service`, không `class: down`.

### 0.6 www vs apex

User liệt kê `giahungtech.com.vn / www` và `chebichat.com.vn / www` → **hai target riêng** (DNS/cert/www có thể lệch). `follow_redirects: true` nên www→apex 301 rồi 200 vẫn healthy.

`www.face-id.cloud` không nằm trong list → không probe.

### 0.7 `xworks.local`

Có thể chỉ resolve trên LAN / split-DNS. Phase 0 khảo sát từ hypervisor: DNS + GET. Nếu NXDOMAIN hoặc không TLS: giữ trong inventory với `severity: warning` và module HTTP (không bắt SSL). Nếu không resolve được: để `enabled: false` cho đến khi có record/hosts.

## 1. Phase 0 — Khảo sát baseline (trước khi bật alert)

### Mục đích

Biết site nào đang 200 thật, site nào Kong no-route, site nào chỉ HTTP, `xworks.local` có resolve không. Tránh bật rule rồi Keep đầy false positive.

### Việc làm

Từ `ght-faceid-server`, với từng URL:

```bash
getent ahostsv4 <host>
curl -sS -o /tmp/body -w '%{http_code} %{url_effective} %{time_total} %{size_download}\n' \
  -L --max-time 15 -A 'kvm-monitoring-blackbox/1.0' 'https://<host>/'
grep -iE 'no Route matched|no Route and no Service|Kong Error' /tmp/body || true
```

Ghi `monitoring/websites/survey.md` (bảng: host, DNS, code cuối, bytes, Kong?, ghi chú). **Không** in secret.

### Tiêu chí xong

Bảng 15 URL (kể cả www). Quyết định `enabled` / `severity` / `scheme` cho `xworks.local`.

### Rollback

Không đổi production.

## 3. Phase 1 — Blackbox module + job + generator

### 3.1 `blackbox/blackbox.yml` — hai module

`http_website` (HTTPS public):

- prober http, timeout **15s**
- GET, `follow_redirects: true`, IPv4 only (đồng bộ icmp/http_2xx)
- `valid_status_codes: [200]`
- `fail_if_not_ssl: true`
- `tls_config.insecure_skip_verify: false`
- `fail_if_body_not_matches_regexp: [".+"]`
- `fail_if_body_matches_regexp`:
  - `(?i)no Route matched`
  - `(?i)no Route and no Service were found`
  - `(?i)no Route and no Service`
- Header `User-Agent: kvm-monitoring-blackbox/1.0` (tránh WAF chặn UA rỗng)

`http_website_plain` (chỉ khi Phase 0 ra HTTP không TLS, ví dụ `xworks.local`):

- Giống trên nhưng `fail_if_not_ssl: false`, không bắt SSL

`http_2xx` **giữ nguyên** — guest/Kong status/Oraybox/AI Box.

Blackbox chạy host network, mount `./blackbox/blackbox.yml`. Đổi module: `docker compose restart blackbox` (không restart Prometheus/Grafana/Keep).

### 3.2 `scripts/gen-website-targets.py`

Giống `gen-aibox-targets.py`: đọc `sites.json`, ghi `prometheus/targets/websites.yml`.

- Target = `url`
- `labels.role=website`, `host`, `app`, `group`
- Nếu `url` bắt đầu `https://` → job dùng module `http_website` (job-level)
- Nếu `http://` → label `__param_module: http_website_plain` **hoặc** tách file `websites-plain.yml` + job thứ hai. Ưu tiên **một job** + `__param_module` trên target plain, vì số lượng nhỏ.

**Không** đặt tên `http-websites.yml` (glob `http*.yml` của job `blackbox-http`).

### 3.3 `prometheus/prometheus.yml` — job mới

```yaml
  - job_name: blackbox-http-website
    scrape_interval: 1m
    scrape_timeout: 20s
    metrics_path: /probe
    params:
      module: [http_website]
    file_sd_configs:
      - files: [/etc/prometheus/targets/websites*.yml]
        refresh_interval: 30s
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: host.docker.internal:9115
```

`scrape_timeout` 20s > module timeout 15s > global 10s. `evaluation_interval` global vẫn 15s.

### 3.4 Kiểm tra probe trước khi alert

```bash
# blackbox trực tiếp
curl -sS 'http://127.0.0.1:9115/probe?module=http_website&target=https://face-id.cloud/' | grep -E 'probe_success|probe_http_status_code|probe_http_ssl'

# sau reload Prometheus
curl -sS 'http://127.0.0.1:9091/api/v1/query?query=probe_success%7Bjob%3D%22blackbox-http-website%22%7D'
```

Kỳ vọng: `probe_success=1` cho site Phase 0 đã 200; `probe_http_status_code=200`; site Kong no-route = 0.

### Rollback Phase 1

Xóa job khỏi `prometheus.yml`, xóa `targets/websites.yml`, revert `blackbox.yml`, restart blackbox, `POST :9091/-/reload`. Không đụng `http.yml` / `AppHTTPDown`.

## 4. Phase 2 — Alert → Alertmanager → Keep

### 4.1 `prometheus/alerts.yml` — group `websites`

```yaml
  - name: websites
    rules:
      - alert: WebsiteHTTPDown
        expr: probe_success{job="blackbox-http-website",role="website"} == 0
        for: 2m
        labels:
          severity: critical
          class: service
        annotations:
          summary: "Website down: {{ $labels.host }}"
          description: "GET {{ $labels.instance }} failed (non-200, empty body, TLS, or Kong no-route) for 2m."
```

`for: 2m` + scrape 1m = ít nhất hai lần fail liên tiếp (lọc blip DNS/WAF).

Nếu inventory có `severity: warning` (`xworks.local`): **hai rule** cùng `alertname` khác `severity` — pattern đã dùng cho HostSwap. Ví dụ:

- `WebsiteHTTPDown` critical: `severity!="warning"` trên target **hoặc** `group!="..."` 
- Gọn hơn: label `tier=prod|optional` trên target; critical khi `tier="prod"`, warning khi `tier="optional"`.

Chọn **`tier`**: `prod` (critical) / `optional` (warning). `xworks.local` = optional sau khi enable.

**Không** sửa `AppHTTPDown`. Query `job="blackbox-http"` giữ nguyên.

### 4.2 Alertmanager

Route hiện tại: `class=service` đi receiver `keep`, `group_by: [alertname, vm, host]`. Label `host=<name>` đủ gom từng site. `repeat_interval` critical 1h.

Inhibit: **không** ức chế WebsiteHTTPDown khi VM/ICMP down — domain public độc lập với guest IP. Không thêm inhibit.

### 4.3 Keep

Đường ingest không đổi. Alert mới hiện inbox `class=service`, fingerprint theo labelset Prometheus.

Bổ sung mock `keep/scripts/mock_alerts.py`:

| ID | Alert | Sev | Labels |
|----|--------|-----|--------|
| S07 | WebsiteHTTPDown face-id | critical | `class=service`, `host=mock-face-id`, `role=website`, `job=blackbox-http-website` |

Cập nhật `keep/TEST-PLAN.md` pack service (kỳ vọng S07 critical, không class=down). **Không** live-drill DROP/iptables trên domain prod.

### 4.4 Reload rule

```bash
docker exec prometheus promtool check rules /etc/prometheus/alerts.yml
curl -sS -X POST http://127.0.0.1:9091/-/reload
curl -sS http://127.0.0.1:9091/api/v1/rules | jq '.data.groups[] | select(.name=="websites")'
```

### Rollback Phase 2

Xóa group `websites` khỏi `alerts.yml`, reload. Mock S07 `resolve`. Dashboard/job có thể giữ (chỉ mất paging).

## 8. Rủi ro và cách xử lý

| Rủi ro | Xử lý |
|--------|--------|
| Site SPA/API trả 200 nhưng trang “no route” Kong | Body regex trong module |
| Site trả 200 + challenge Cloudflare | Survey Phase 0; nếu fail hàng loạt, nới UA hoặc đánh `optional` |
| Cert hết hạn | TLS verify → `WebsiteHTTPDown` (đúng ý public HTTPS) |
| www redirect loop | `probe_success=0`; sửa DNS/Kong, không nới 301 làm success |
| `xworks.local` NXDOMAIN | `enabled: false` cho đến khi resolve |
| WAF rate-limit scrape 15s | Job 1m, 15 target ≈ 15 GET/phút |
| False positive blip | `for: 2m` |
| Trộn alert guest HTTP | Job/role/alertname tách; không đụng `http.yml` |
| glob `http*.yml` nuốt file mới | Tên `websites.yml`, không `http-*.yml` |
